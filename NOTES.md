# Заметки: идеи вне рамок текущего этапа

Сюда пишется то, что всплывает по ходу работы, но в рамки этапа не входит (TASK2 §«Порядок работы», п. 4). Не реализовано.

## Из этапа 0

- **Проверка правил humanizer кодом.** Сейчас это только инструкции модели. Детерминированно вычистить деепричастный хвост или триаду нельзя (обрежешь смысл), но можно было бы **подсвечивать** найденные маркеры в готовом письме, чтобы правка была точечной. В рамки этапа 0 не входит.
- **Второй проход LLM для humanizer.** Отдельный запрос «перепиши по правилам humanizer» после генерации даёт более предсказуемый результат, чем правила в промпте, но стоит +1 вызов и +10-20 с на письмо. Имеет смысл обсуждать, когда генерация переедет на сервер (этап 1) и станет видна реальная цена вызовов. Потребует защиты: второй проход не должен затирать дословную фразу компании и привносить факты, которых нет в CV.
- **Контакты в тексте письма.** Сейчас контакты копируются отдельно. Можно было бы подставлять их в подпись (ТЗ этого не просит, подпись задаётся шаблоном).
- **Автоопределение языка подписи.** Сделано по доле кириллицы в готовом письме. Если появятся другие языки, понадобится что-то серьёзнее эвристики.
- **Размер бандла.** `dist/background.js` около 1 МБ из-за трёх SDK провайдеров в service worker. После переноса вызовов на сервер (этап 1) проблема уходит сама.

## Из этапа 1 (ещё не начат)

- **Стабильный ID расширения для CORS.** `chrome-extension://<ID>` у unpacked-расширения меняется при смене пути папки. Чтобы origin был постоянным, в манифест нужно добавить поле `key` с публичным ключом.
- **Офлайн-режим.** После переезда на сервер расширение перестанет работать без него. Возможный компромисс на будущее: кэш последнего результата и очередь отправки.
