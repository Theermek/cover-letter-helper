# AI Cover Letter Assistant

Расширение для Chrome, которое помогает откликаться на вакансии: вставляете текст вакансии, получаете живое сопроводительное письмо на основе своего CV, а расширение попутно копит статистику того, что реально требует рынок.

Работает по модели **BYOK** (bring your own key): вы подключаете собственный ключ OpenAI, Anthropic или Google Gemini.

Данные постепенно переезжают на собственный сервер (Node + Postgres), который запускается рядом — локально или на вашем хостинге. На сервере живут CV, контакты, шаблоны подписи, сохранённые вакансии и расчёт статистики, поэтому **без запущенного сервера расширение не работает**. В браузере пока остаются только настройки, ключи провайдеров и сам вызов LLM.

## Что умеет

- **Генерация письма.** По тексту вакансии и вашему CV. Язык (RU / EN / как в вакансии), длина (короткое / среднее / длинное) и свободное поле «дополнительные пожелания».
- **Живой стиль.** Письмо пишется разговорно-деловым тоном, без канцелярита и штампов вроде «с огромным энтузиазмом» или «passionate». Длинные тире, многоточия одним символом, эмодзи и markdown вычищаются кодом после генерации.
- **Без следов ИИ.** В промпте отдельный блок правил против характерных признаков генерации: пафос и «служит свидетельством», деепричастные хвосты вроде «демонстрируя системный подход», триады, конструкции «не просто X, а Y», хеджирование, пассив, шаблонные концовки, ровный машинный ритм. Основан на скилле `humanizer` в этом же репозитории.
- **Честность важнее всего.** Модель не придумывает опыт, которого нет в CV, даже если этого просит вакансия или вы сами.
- **Требования компании к письму.** Если в вакансии спрятано «начните письмо со слова X» или «пришлите только кодовое слово», расширение это находит, показывает отдельным блоком и выполняет дословно.
- **База вакансий.** Каждая генерация сохраняется в Postgres, из вакансии извлекаются навыки. Повторная генерация по той же вакансии обновляет запись, а не плодит дубликаты: уникальный индекс по хэшу текста не даёт появиться второй.
- **Статистика рынка.** Топ-10 hard и топ-10 soft навыков по всем сохранённым вакансиям: в скольких процентах вакансий встречается, как часто обязателен, в каких формулировках. Считает сервер обычным кодом, без обращения к LLM.
- **Подпись.** Чекбокс «Добавить подпись» у кнопки генерации. Подпись дописывается кодом после генерации (а не моделью), шаблоны отдельно для русских и английских писем и редактируются в настройках. При повторной генерации не дублируется.
- **Мои контакты.** Список пар «Telegram / @username», «GitHub / ...» и т.д. Хранится локально, редактируется в настройках, в popup раскрывается одной строкой и копируется по иконке — чтобы вставлять в отклик без поиска по заметкам.
- **Экспорт и импорт.** Выгрузка всего в JSON и загрузка обратно с дедупликацией по хэшу текста. Импорт никогда не затирает уже заполненные CV, контакты и подпись. Отдельная кнопка переносит на сервер данные, оставшиеся в браузере с прошлых версий. API-ключи в экспорт не попадают.

## Установка

Готовой сборки в Chrome Web Store пока нет, расширение ставится из исходников.

```bash
git clone <repo-url>
cd cover-letter-helper
npm install
npm run build
```

Затем в Chrome:

1. Откройте `chrome://extensions`.
2. Включите **Режим разработчика** (переключатель справа сверху).
3. Нажмите **Загрузить распакованное расширение** и выберите папку `dist`.

> Если `npm install` падает с ошибкой `Cannot read properties of null (reading 'edgesOut')` — это баг npm 10.8 при разрешении опциональных peer-зависимостей vitest. Помогает `npm install --legacy-peer-deps`.

## Сервер

Профиль (CV, контакты, подписи) хранится в Postgres, расширение читает его по HTTP. Поэтому перед использованием нужно поднять базу и сервер.

```bash
docker compose up -d          # Postgres 17 с расширением pgvector, порт 5433
cd server
cp .env.example .env          # и впишите DATABASE_URL и API_TOKEN
npm install
npm run db:migrate            # накатить миграции из server/drizzle
npm run dev                   # сервер на http://localhost:3000
curl -s localhost:3000/health # {"status":"ok","db":"ok"}
```

`API_TOKEN` — произвольная строка не короче 16 символов, её же нужно будет ввести в настройках расширения. Сгенерировать можно так:

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

Данные базы лежат в docker-томе `clh_pgdata` и переживают перезапуск контейнера. `docker compose down -v` удаляет их вместе с томом — после этого миграции накатываются заново на пустую базу.

Переменные окружения сервера описаны в `server/.env.example`; `server/src/config/env.ts` проверяет их при старте и падает с понятным сообщением, если чего-то не хватает. Файлы `.env` в git не попадают.

## Первая настройка

При первом открытии расширение покажет экран настройки:

0. **Укажите сервер** — на странице настроек, блок «Сервер»: адрес (по умолчанию `http://localhost:3000`) и токен из `API_TOKEN`. Кнопка **«Проверить соединение»** дёргает `/health` и затем читает профиль с токеном, то есть проверяет и доступность, и права.
1. **Выберите провайдера** — OpenAI, Anthropic или Google Gemini.
2. **Вставьте API-ключ.** Ссылка «Где взять ключ» ведёт в нужный кабинет.
3. **Выберите модель** или оставьте модель по умолчанию. Можно вписать произвольный id модели или нажать «Обновить список из API», чтобы подтянуть актуальные модели вашего аккаунта.
4. Нажмите **«Проверить и сохранить»** — расширение отправит короткий тестовый запрос и сообщит понятным текстом, если ключ не принят или нет доступа к модели.
5. **Добавьте CV** — текстом или загрузкой PDF (текст из PDF извлекается локально и показывается для правки). Без CV генерация заблокирована.

CV и модель можно поменять в любой момент на странице настроек. CV, контакты и подписи при сохранении уходят на сервер, ключ провайдера остаётся в браузере.

## Как пользоваться

- Нажмите на иконку расширения, вставьте текст вакансии, нажмите **«Сгенерировать»**.
- Если в popup тесно, кнопка **«Открыть в окне»** переносит то же состояние на полноразмерную страницу.
- Письмо можно править прямо в поле — правки сохраняются в базу.
- Можно выделить текст вакансии прямо на странице сайта и выбрать в контекстном меню **«Сгенерировать сопроводительное по выделенному тексту»**.
- Копирование письма и повторная генерация — иконки `⧉` и `↻` в правом верхнем углу поля письма.
- Чекбокс **«Добавить подпись»** в том же ряду, что кнопка генерации; состояние запоминается.
- Блок **«Мои контакты»** под кнопкой генерации: раскрывается нажатием, у каждого контакта своя иконка копирования.
- Иконка `▤` открывает страницу с топ-10 навыков и списком сохранённых вакансий, `⚙` — настройки.

Генерация идёт в фоновом процессе расширения, поэтому popup можно спокойно закрыть: когда вы откроете его снова, результат будет на месте.

## Приватность

- CV, контакты, шаблоны подписи, вакансии и письма хранятся в **вашей** базе Postgres, к которой обращается только ваш сервер. Никакой телеметрии и сторонних сервисов в проекте нет.
- Настройки, API-ключи провайдеров, адрес и токен сервера остаются **локально** в браузере (`chrome.storage.local`).
- Кнопка «Удалить локальные данные браузера» стирает только браузерную часть. Данные на сервере удаляются в самой базе — одной кнопки, необратимо выносящей базу, в расширении нет намеренно.
- Сервер доступен только с токеном (`Authorization: Bearer`), CORS открыт лишь для origin расширения. Токен не логируется и не возвращается в ответах.
- API-ключ отправляется **только** в API выбранного вами провайдера и никуда больше. Он не логируется и не попадает в экспорт.
- Текст вакансии и ваше CV уходят в API выбранного провайдера — это необходимо для генерации. Далее действует политика этого провайдера.
- Загруженный PDF не сохраняется: из него извлекается текст, и дальше источником правды является только текст CV.
- Кнопка **«Удалить все данные»** в настройках стирает всё без следа.

Учтите: `chrome.storage.local` не шифруется. Любой, у кого есть доступ к вашему профилю Chrome, может прочитать сохранённый ключ. Это обычное свойство расширений с BYOK.

## Разработка

```bash
npm run dev        # сборка в watch-режиме (после изменений обновите расширение в chrome://extensions)
npm run typecheck  # tsc --noEmit, strict
npm run test       # unit-тесты (Vitest)
npm run check      # проверка целостности собранного расширения
npm run verify     # typecheck + тесты + сборка с проверкой
npm run icons      # перегенерировать иконки
```

Сервер — отдельный проект со своим `package.json`:

```bash
cd server
npm run dev          # tsx watch, перезапуск на изменениях
npm run typecheck    # tsc --noEmit, strict
npm run test         # Vitest + supertest, без обращения к реальной базе
npm run db:generate  # drizzle-kit: SQL-миграция из изменений в схеме
npm run db:migrate   # накатить миграции
npm run verify       # typecheck + тесты
```

### Структура

```
src/
  background/   service worker: роутер сообщений, генерация, контекстное меню
  providers/    адаптеры OpenAI / Anthropic / Gemini под единым интерфейсом
  prompts/      системный промпт, few-shot примеры, сборка пользовательского промпта
  schema/       zod-схема ответа модели (контракт + валидация в одном месте)
  storage/      chrome.storage.local (настройки, контакты) и IndexedDB (вакансии)
  lib/          санитайзер, хэш, статистика, нормализация навыков, PDF, экспорт
  config/       провайдеры, модели, длины, запрещённые фразы, навыки, строки UI
  ui/           общие компоненты, в том числе экран генерации для popup и editor
  api/          единственное место с fetch к серверу + типизированные вызовы
  popup/ options/ stats/ editor/   точки входа страниц

server/
  src/config/     zod-схема переменных окружения, проверка при старте
  src/db/         пул pg, Drizzle, схема таблиц, запуск миграций
  src/middleware/ Bearer-авторизация, единый формат ошибок, логирование
  src/modules/    вертикальные слои по сущностям: routes → service → repository
    profile/      CV, контакты, подписи
    vacancies/    CRUD вакансий и эндпоинт статистики
    stats/        чистый расчёт: статистика, нормализация навыков, синонимы
    import/       приём файла экспорта
  drizzle/        SQL-миграции, лежат в git и накатываются по порядку

shared/           код, одинаковый для сервера и расширения: DTO-схемы, дефолты
```

`shared/dto/profile.ts` — одна zod-схема на две стороны: сервер проверяет ею входящий запрос, расширение — пришедший ответ. Поэтому рассинхронизация контракта ломает typecheck, а не поведение в рантайме.

### Что правится одним файлом

- **Новые модели** — `src/config/providers.ts` (или кнопка «Обновить список из API» без правки кода).
- **Запрещённые штампы** — `src/config/bannedPhrases.ts`.
- **Правила против признаков ИИ** — `src/prompts/humanizer.ts`.
- **Синонимы навыков** — `server/src/modules/stats/skillAliases.ts`. Применяются и при чтении, поэтому пополнение словаря улучшает статистику и по уже сохранённым вакансиям, без миграции данных.
- **Категории soft skills** — `shared/vocabulary.ts` (там же грейды и форматы работы: один список для сервера и расширения).
- **Ориентиры длины** — `src/config/lengths.ts`.
- **Шаблоны подписи по умолчанию** — `shared/defaults.ts` (их использует и сервер при создании профиля, и расширение; редактирование в настройках без правки кода).
- **Тексты интерфейса** — `src/config/strings.ts`.

Контакты лежат за интерфейсом `ContactsStore` в `src/storage/contacts.ts`: компоненты не обращаются к хранилищу напрямую. Благодаря этому переезд на сервер потребовал заменить в этом файле одну реализацию на другую (`chromeStorageContacts` → `apiContacts`), не тронув ни один компонент.
